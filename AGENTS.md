# OpenChamber PTT agent and engineering invariants

See [README](README.md) for the overview, prerequisites, build commands, and quick start, and [GLOSSARY](GLOSSARY.md) for canonical domain terms. This file records non-obvious runtime, protocol, ABI, and verification invariants for contributors and agents.

## 1. Service lifecycle and audio (`PttForegroundService`, `BluetoothAudioRouter`, `TelecomCaptureCoordinator`)
- **Promote standalone TTS to foreground.** Never run active PTT or **Read aloud** (`readPreviousMessage`) solely under an Activity `bindService` binding. When starting `Read aloud` from `DISARMED`, set `promotedForStandaloneTts = true`, call `ContextCompat.startForegroundService(..., ACTION_ENSURE_MEDIA_FOREGROUND)` and `startForegroundWithState(SPEAKING_TTS, ServiceInfo.FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK)`, and tear down via `stopForegroundAndSelf()` on `TtsFinished`, `Stop`, or `Error`. `resolveForegroundServiceType()` must return `FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK` only whenever `promotedForStandaloneTts || state == DISARMED` so screen-locked stop intents never request `FOREGROUND_SERVICE_TYPE_MICROPHONE` from the background on Android 14+. Armed PTT uses `mediaPlayback | microphone`.
- **Media button ownership on Android 14+ & vocal cue playback (`EarconPlayer`, `CuePlayer`, `VocalCuePackWarmer`).** Keep `MediaSessionCompat` active and play `AudioTrack` (`MODE_STATIC`) cues via `EarconPlayer` (switching between `USAGE_VOICE_COMMUNICATION` when `bluetoothAudioRouter.isScoPinned || telecomCaptureCoordinator.isCallActive` is true and `USAGE_MEDIA` otherwise) so Android routes headset `ACTION_MEDIA_BUTTON` events to `OpenChamberPttMediaSession` while screen-locked. `EarconPlayer` pre-decodes bundled `res/raw/earcon_*.ogg` (`romainsimon/uisfx` `studio` theme, `CC0-1.0`) via `AudioCodecDecoder` (`MediaExtractor`/`MediaCodec`) and falls back to synthetic PCM16 tones when `Context == null` (JVM unit tests). `CuePlayer` plays cached vocal clips (`AudioCueMode`: `HYBRID` default, `VOCAL`, `TONES`, warmed in the background by `VocalCuePackWarmer`) through `EarconPlayer.playCustomClip` without mutating `PttState` (preserving instant `SEND_GRACE` undo and media-button ownership), gating on-device vocal latency bridges on `ttsPlayer.isAudibleOutputActive` rather than `isSpeaking`; live-mic cues (`REC_START`, `MAX_DURATION_WARNING`) strictly remain non-verbal tones, and `StartRecording` stops non-`REC_START` cues via `stopUnlessRecStart()`.
- **Unified PCM16 `AudioTrack` output & cold-sink coordination (`AudioCodecDecoder`, `AudioOutputCoordinator`, `TtsPlayer`).** All cloud TTS payloads (RIFF WAV and encoded formats such as OpenAI MP3) decode to PCM16 via `WavParser` / `AudioCodecDecoder.decodeEncodedBytes` and play directly through `AudioTrack` (never temp-file `MediaPlayer`). `AudioOutputCoordinator` serializes speech after active cues (`70 ms` post-cue drain gap), ignores `useCommunicationUsage == true` cues for A2DP warmth, invalidates sink warmth (`invalidateSinkWarmth()`) across SCO/Telecom capture transitions, and prepends a `160 ms` TPDF-dithered pre-roll (`AudioPreroll`) when the A2DP media sink has been idle `> 2.5 s`. Slow reply synthesis (`> 450 ms`) emits a latency-bridge cue (`REPLY_PREPARING` / `READING_REPLY`) and `200 ms` A2DP comfort-dither keep-alive chunks (capped at `12 s`) to keep Bluetooth A2DP awake without clipping initial syllables.
- **Capture transport vs. playback focus (`PttStateMachine`, `BluetoothAudioRouter`, `TelecomCaptureCoordinator`).** `PttStateMachine` separates `AcquireCaptureAudio` / `ReleaseCaptureAudio` (strictly bracketing `PttState.RECORDING`) from `AcquirePlaybackFocus` / `ReleasePlaybackFocus` (strictly bracketing `SPEAKING_TTS` and `STAGED_DRAFT_SPEAKING` with `USAGE_MEDIA` in `MODE_NORMAL`, never pinning SCO so TTS stays on stereo A2DP + AVRCP and never triggers mic-less HFP SCO drops). During `RECORDING`:
  - `pinBluetoothSco == false` uses `USAGE_MEDIA` focus and `VOICE_RECOGNITION`.
  - `pinBluetoothSco == true && !telecomCallForRecording` pins Classic HFP SCO (`VOICE_COMMUNICATION`) and monitors `OnCommunicationDeviceChangedListener` (API 31+) + `ACTION_SCO_AUDIO_STATE_UPDATED` so `AT+CKPD=200` SCO-drop taps trigger `SingleTap` stop while the headset remains connected.
  - `pinBluetoothSco == true && telecomCallForRecording` (`androidx.core:core-telecom:1.0.1`, `minCompileSdk = 34`, `MANAGE_OWN_CALLS`) suppresses `BluetoothAudioRouter` SCO/mode/focus mutations, awaits `CallsManager.addCall` (`callCapabilities = 0`) + `TYPE_BLUETOOTH` (`<= 1_200 ms`) inside `AudioBurstRecorder.executeBurst` before playing `REC_START` and opening `AudioRecord(VOICE_COMMUNICATION)`, maps headset hangup `onDisconnect` via `TelecomHangupAction` (`QUICK_SEND` -> `SingleTap`, `SEND_IMMEDIATELY` -> `SendCaptureImmediately`, `STAGE_DRAFT` -> `StageCapture`), re-asserts `MediaSessionCompat` active state on disconnect, and stages silently (`StageCapture`) on cellular-call interruption without auto-sending.
- **Ephemeral recording & draft stop surfaces & live audio diagnostics (`RecordingVolumeKeyController`, `RecordingMirrorNotificationController`, `AudioDebugBuffer`).**
  - Opt-in `RecordingVolumeKeyController` attaches `VolumeProviderCompat(VOLUME_CONTROL_RELATIVE, 100, 50)` (`setPlaybackToRemote`) strictly while **screen is off** (`!powerManager.isInteractive`, monitored via `ACTION_SCREEN_OFF`/`ACTION_SCREEN_ON`) during `RECORDING` (`VolumeKeyRecordingMode`) and `STAGED_DRAFT` / `STAGED_DRAFT_SPEAKING` (`VolumeKeyDraftMode`) *after* `PlaybackStateCompat.STATE_PLAYING` is set (`STAGED_DRAFT` also holds `STATE_PLAYING` solely while screen-off draft volume keys are enabled), ignoring `direction == 0` (`ACTION_UP`) and unmapped directions (`SEND_ONLY` Vol-), debouncing per-episode triggers, and restoring `setPlaybackToLocal(STREAM_MUSIC)` immediately on trigger/screen-on/exit/destroy.
  - `RecordingMirrorNotificationController` posts `RECORDING_MIRROR_NOTIFICATION_ID = 1004` once per recording burst on `openchamber_ptt_recording_mirror_v1` (`IMPORTANCE_DEFAULT`, `sound = null`, `vibration = false`, `ongoing = false`, `localOnly = false`, `VISIBILITY_PUBLIC`, distinct group `"openchamber_ptt_recording_mirror"`, no `CATEGORY_SERVICE` or `setSilent(true)`) with an explicit `exported="false"` `RecordingNotificationActionReceiver` (`RECORDING`-only stop guard so delayed BLE watch taps never start a new recording or undo `SEND_GRACE`).
  - `AudioPlatformDiagnosticMonitor` feeds `AudioDebugRegistry.shared` (`300`-entry ring buffer rendered in `AudioDebugActivity`) and must register Bluetooth/audio system broadcast receivers with `ContextCompat.RECEIVER_EXPORTED` so Android 14+ `BroadcastSkipPolicy` does not drop `UID 1002` (`com.android.bluetooth`) broadcasts.
- **Headset cadence & state machine (`MediaButtonGestureDetector`, `PttStateMachine`).** `MediaButtonGestureDetector` normalizes rapid `PLAY`/`PAUSE`/`PLAY_PAUSE`/`HEADSETHOOK` taps (`350 ms` / `240 ms`) plus AVRCP `KEYCODE_MEDIA_NEXT`/`PREVIOUS`/`STOP`, honoring `HeadsetTapMode` (`SINGLE_ONLY` forces `IMMEDIATE_SINGLE` across all states for 0ms single-tap response on Shokz headsets) and `avrcpTrackControlsEnabled` (gating `NEXT`/`PREVIOUS`), and bypassing multi-tap debounce (`IMMEDIATE_SINGLE`) in `SEND_GRACE` and `SPEAKING_TTS` so undo and barge-in stay instant. `MAX_UTTERANCE_MS = 300_000L` plays a warning earcon at `285_000L` and auto-stages (`StageCapture`) on timeout rather than auto-sending.

## 2. Protocol and timing contracts
- **WebSocket upgrades.** `OpenChamberHttp` must attach a canonical same-host `Origin` header (`canonicalOrigin`) on `WS /api/dictation/ws` and `WS /api/global/event/ws`.
- **Dictation handshake.** `DictationClient` must wait for the initial server `ack` (`ackSeq: -1`) before streaming PCM chunks.
- **Voice tag contract.** `PttForegroundService` prepends `[voice]` (`VOICE_PROMPT_PREFIX`) to outgoing PTT prompts, and `SessionClient.fetchLatestTurn` strips it before populating UI `lastTranscript`.
- **Permission alert grace period.** Keep `PERMISSION_ALERT_DELAY_MS = 4000L` before announcing or notifying tool approvals, and cancel pending alerts immediately on `TurnEvent.PermissionResolved`.
- **Send grace & telemetry (`VoiceUxLogger`).** Quick single-tap stops enter `SEND_GRACE` (`2_500L`) before `SessionClient.sendPrompt`; any re-tap pulls the turn into a durable draft. `VoiceUxLogger` records structured JSONL performance/UX metrics (`filesDir/voice_ux_log.jsonl`, `OpenChamberUx` logcat tag).

## 3. Multi-server storage and auth (`TokenStore`, `OpenChamberHttp`, `SessionRepository`)
- **Origin-scoped tokens.** `OpenChamberHttp.createClient` resolves bearer tokens per request URL (`tokenForUrlProvider`) so concurrent multi-server fetches (`SessionRepository.listAllServerSessions`) never send one server's token to another.
- **Per-server `401` isolation.** HTTP `401` in `MainActivity`, `BubbleActivity`, or `PttForegroundService` clears auth only for the failing `serverId` (`tokenStore.clearAuth(serverId)`). `/auth/session` always passes `trustDevice = true` with a persistent per-install `dedupeKey`.
- **Session switch continuity & durable drafts.** `loadedSessionKey` in `PttForegroundService` must use `TokenStore.sessionKeyFor(serverId, pinnedSession)` (`${serverId}|${sessionId}|${directory}`). `StagedDraft`s persist per session key across restarts, `Disarm`, and session switches, and are cleared only on successful `sendPrompt` or explicit Discard. Switching servers or sessions preserves `ARMED_IDLE` / `STAGED_DRAFT` and updates the notification, Bubble, and transcript; switching mid-turn (`PttState.isBusyWithTurn`) disarms first.

## 4. STT, TTS, and ML Kit GenAI invariants
- **Global vs per-server voice config & role routing (`VoiceRole`, `VoiceRoleResolver`, `TokenStore`).** On-device `mlKitVoice` and `systemVoice`, along with hardware/wearable controls (`pinBluetoothSco`, `bluetoothCaptureMode` / `telecomCallForRecording`, `telecomHangupAction`, `headsetTapMode`, `avrcpTrackControlsEnabled`, `volumeKeyRecordingMode` / `volumeKeyStopRecording`, `volumeKeyDraftMode`, `mirrorRecordingNotification`), stay strictly global across servers. `ttsPipeline`, `ttsInputMode`, `spokenDetailLevel`, `audioCueMode`, `geminiVoice`, `openAiVoice`, per-role cloud/engine overrides (`ServerRoleCloudOverride`), `sttEngine`, `sttFallbackToParakeet`, `quickTurnDirectAnswer`, and `quickTranscriptCleanup` resolve through `TokenStore.getEffective*` (per-server `ServerVoiceOverride` when enabled, otherwise global). `AgentTurnRunner` routes session replies and `Read aloud` to `VoiceRole.AGENT`, local direct answers, live-tuning confirmations, `RAW` permission alerts, and staged draft readback (`STAGED_DRAFT_SPEAKING`) to `VoiceRole.OPERATOR`, and short vocal cues to `VoiceRole.CUE`. `VoiceRoleResolver` guarantees collision-free distinct `Auto` defaults across Gemini, OpenAI, ML Kit, and System voices and honors optional per-role `preferredEngine` pinning with base-pipeline fallback. Idle voice previews run via `TtsPlayer.speakPreview` (`RAW`, `kind = "preview"`, no engine fallback, no `PttState` mutation).
- **Async reply queueing, settlement & audible barge-in (`SessionResponseController`, `AgentTurnRunner`, `TtsPlayer`).**
  - `AutoSpeakWatermark` (`Uninitialized` -> `Established`) never skips post-arm HTTP baseline verification from stale `windowCache`, counts only `TurnEvent.Completed` (never `SyntheticArrived`) during arming, and aligns initial `SessionReplyCursor.armedBaselineMessageId` when `cursor == null` so live arrivals during `arm()` play in order without leaking pre-arm desktop history.
  - `AgentTurnRunner.runAgentTurn` threads `sentUserMessageId = SessionClient.sendPrompt(...)` into 4-state `PromptTurnSettlement` (`ReadyToSpeak`, `SettledNoSpeech`, `TurnStillRunning`, `FlushLagRetryNeeded`) and keeps WS turn-event syncing active across `activePromptTurn`.
  - `TtsPlayer` serializes concurrent callers fairly on `playbackMutex` with an isolated inner child `Job` and `abortEpoch` (returning `TtsPlaybackResult.COMPLETED` or `ABORTED` without cancelling caller parent coroutines), while `AgentTurnRunner`'s `SpeechCoordinator` queues `DrainAutoReplies`, `EnqueueOperatorSpeech`, and `EnqueuePermissionAlert` in FIFO order.
  - `onUserBargeIn` advances `lastHeardMessageId` only after `ActiveSpeechProgress.Audible` reaches `>= 1_500 ms` (or `>= 50%` of clips `< 3_000 ms`, `estimatedDurationMs > 0L`). Involuntary `PttEvent.PlaybackInterruptedByTransport` (`AUDIOFOCUS_LOSS*` / `ACTION_AUDIO_BECOMING_NOISY`) pauses auto-speak without marking the item heard and is excluded from immediate idle auto-speak re-triggering.
- **Two-tier TTS cache (`TtsCache`, `TtsClient`, `SessionResponseController`).** `TtsCache` (`cacheDir/openchamber_tts_cache/v1`) caches prepared speech text (`text/`, `4 MB` / 2,000 entries + in-memory LRU) and synthesized cloud audio envelopes (`audio/`, `64 MB`, atomic temp-file writes) with ref-counted `SingleFlight` deduplication (partial caller cancellation preserves the shared flight; all-waiter cancellation cancels it). Never poison `TtsInputMode.SUMMARIZED` cache entries with sanitized fallbacks on transient small-model failures. `SessionResponseController` hydrates focused spoken summaries from `TtsCache` on session/config changes without network requests.
- **Speech input modes & draft readback (`TtsClient`, `PromptOrganizer`).**
  - `TtsInputMode.SUMMARIZED` (`Spoken`) acts as a written-to-spoken translator via `POST /api/small-model/generate` parameterized by `SpokenDetailLevel` (`ESSENTIALS`, `BALANCED`, `DETAILED`) whenever length `>= 180` chars or markdown/code/paths/URLs are present, normalizing stray markdown locally without calling `/api/text/summarize` (whose `sanitizeForTTS` strips backticked code and `/paths`); `/api/text/summarize` (`mode="tts"`) is used only as a fallback if small-model translation fails or under `TtsInputMode.SANITIZED`.
  - Keep spoken output tag-free (no `<...>` / `[...]` tags, SSML, or IPA) because `TtsPlayer` falls back across Gemini, Kokoro, ML Kit, Android System, and OpenAI, and OpenChamber `/api/tts/speak` strips `instructions` whenever `baseURL` (`GEMINI_BRIDGE`) is set.
  - `PromptOrganizer` runs quick post-ASR cleanup and Smart Merge/Revise draft organization via `POST /api/small-model/generate` with strict timeouts and deterministic fallback.
  - Staged draft TTS readback (`STAGED_DRAFT_SPEAKING`) must pass `inputModeOverride = TtsInputMode.RAW` to `TtsPlayer.speak` so `/api/text/summarize` (200-char threshold) does not truncate or re-summarize the organized draft.
- **Provider voice isolation.** Never reuse `gemini-tts-bridge` voice IDs for `OPENAI_CLOUD` (`VoiceRoleResolver` validates OpenAI voice IDs via `TtsClient.normalizeOpenAiVoiceOrNull`). Keep `MLKIT_GENAI` and `ANDROID_SYSTEM` as distinct pipeline entries.
- **External `gemini-tts-bridge` and `gemini-decisions-bridge` dependencies.**
  - `TtsClient.fetchVoices` calls `GET /v1/audio/voices` via `POST /api/guests/gemini-tts-bridge/service/request` (`category=featured`), provided by the `gemini-tts-bridge` OpenChamber extension.
  - `VoiceControlPlane.evaluateTurn` classifies quick turns (`fromStagedDraft == false`) via `gemini-decision-1` (`POST /api/guests/gemini-decisions-bridge/service/request` -> `/v1/systemone`) into `PASS_THROUGH`, `LIVE_TUNING` (`tuning_detail` + `tuning_mode`, always active), or `ANSWER_DIRECTLY` (via `/api/small-model/generate` using `VoiceReplyContext`), failing open to `PASS_THROUGH` without clobbering `lastReply` or `spokenSummary`. `ANSWER_DIRECTLY` interception is gated by `TokenStore.getEffectiveQuickTurnDirectAnswer` (default `false` so coordinator sessions receive prompts unmodified unless opted in via Settings).
  - **Terminology boundary (`VoiceControlPlane` vs. `voice` agent):** Distinguish the **app-level voice router** (`VoiceControlPlane.kt` in `openchamber-ptt-android`, which intercepts quick spoken utterances locally for `LIVE_TUNING` and `ANSWER_DIRECTLY` before forwarding prompts) from the **session-level voice coordinator** (the `voice` OpenCode agent that runs inside OpenChamber sessions, administers coding/subagent work, and receives async `returnResult: true` wakeups).
- **ML Kit GenAI AAR `$default` ABI hazard.** `com.google.mlkit:genai-text-to-speech:1.0.0-alpha1` strips Kotlin `$default` synthetic helpers and constructors from its packaged AAR (`speechSynthesizerOptions$default`, `SpeechSynthesizerRequest.<init>(..., DefaultConstructorMarker)`).
  - Always use `SpeechSynthesizerOptions.builder(locale)...build()` and explicit `SpeechSynthesizerRequest(input, audioAttributes, queueMode)`.
  - Never collapse ML Kit `getClient` or `checkStatus` errors into a bare `"Unavailable"` string; include raw status or exception details plus `com.google.android.tts` (`>= 210665810`), `GoogleAsrService`, and `com.google.android.aicore` diagnostics.
  - Normalize English locales (`en*`) to `Locale.US` in `MlKitSttClient`.

## 5. Network, UI, and verification constraints
- **Network security.** `app/src/main/res/xml/network_security_config.xml` intentionally permits cleartext HTTP (`cleartextTrafficPermitted="true"`) and trusts both `system` and `user` CA anchors for Tailscale HTTP and local dev CAs.
- **APK size and Compose rules.** Avoid `material-icons-extended` and use minimal vector drawables in `res/drawable/`. Maintain `>=48dp` touch targets, `ContentType.Password` with `LocalAutofillManager` on password fields, `skipPartiallyExpanded = true` on multi-section `ModalBottomSheet`s, and `FlowRow` for wrapping action button groups.
- **Emulator vs hardware verification.**
  - The `openchamber_api35` emulator lacks `com.google.android.tts` (`GoogleAsrService`) and `com.google.android.aicore`, so ML Kit GenAI STT/TTS always reports `Unavailable` on the emulator and requires physical Pixel 8+ or Galaxy S25+ hardware with a locked bootloader for end-to-end verification.
  - For deterministic emulator UI/session-selector QA without a live OpenChamber host, start `bun scripts/mock-openchamber-server.mjs` and connect on `openchamber_api35` via `http://10.0.2.2:18401` (and `http://10.0.2.2:18402` for multi-server chips; supports `--page-size`, `--unauthorized-port`, and `--log`). Use `bun scripts/capture-pixel10-pro-screenshot.mjs` to capture clean `1280x2856 @ 480 dpi` Pixel 10 Pro screenshots (including for `README.md`).
  - Verify UI changes on `openchamber_api35` in dark and light modes, and verify service foreground promotion via `adb shell dumpsys activity services com.openchamber.ptt`.
  - Always include the full path to the built APK wrapped in inline code backticks (e.g., `` `/path/to/openchamber-ptt-android/app/build/outputs/apk/debug/app-debug.apk` ``) in final replies after building so OpenChamber auto-links it for direct install from the chat UI.
